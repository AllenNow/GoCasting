# 渔具销售与库存管理系统（CastingStore）

微信小程序（内部管理工具）+ 微信云开发。设计依据：[销售库存系统设计方案](../../docs/渔具店系统/销售库存系统设计方案.md)。

## 一、技术结构

```
CastingStore/
├── cloudfunctions/api/          统一 API 云函数（鉴权 / 权限 / 字段裁剪 / 事务）
│   ├── index.js                 入口，action 路由
│   ├── lib/                     权限、脱敏、工具、路由
│   └── actions/                 auth / init / product / supplier / purchase / inventory / order / report / user
├── miniprogram/
│   ├── app.json                 5 个 tab：首页 / 订单 / 库存 / 报表 / 我的
│   ├── utils/                   api.ts、auth.ts、format.ts、ui.ts、config.ts
│   └── pages/                   首页、订单、库存、采购、商品、供应商、报表、我的、用户
└── project.config.json          miniprogramRoot + cloudfunctionRoot
```

所有读写都走 `api` 云函数，小程序端不直连数据库。

## 二、首次部署（按顺序）

1. 用微信开发者工具导入 `CastingStore` 目录（appid 已配置为 `wxd410c38bff214c76`）。
2. 左上角「云开发」→ 开通/选择环境。
   - 若使用非默认环境：把环境 ID 填到 `miniprogram/utils/config.ts` 的 `ENV_ID`；留空则使用开发者工具当前环境。
3. 右键 `cloudfunctions/api` → **上传并部署：云端安装依赖**。
4. 云开发控制台 → 云函数 → `api` → 配置：把超时时间改为 **20 秒**（首次初始化要建 12 个集合）。
5. 编译小程序，进入「首页」或「我的」→ 点 **初始化系统**。
   - 自动创建全部集合、默认仓（WH01），并把当前微信号设为 **老板 / owner**。
6. 数据库权限：把所有集合的权限设为 **仅管理端可读写**（所有访问都经过云函数）。
7. 建议索引（云开发控制台 → 数据库 → 索引管理）。带 `+` 的是复合索引，按顺序创建：

| 集合 | 索引字段 |
|------|----------|
| users | openid（唯一）、created_at |
| products | sku_code（唯一）、barcode、category + created_at、status + created_at |
| inventory | product_id、product_id + warehouse_id（唯一）、updated_at |
| inventory_txns | product_id + created_at、type + created_at、created_at |
| purchase_orders | created_at、status + created_at、supplier_id + created_at |
| orders | created_at、status + created_at、platform_order_no、supplier_id + created_at |
| after_sales | order_id + created_at、status + created_at |
| stocktakes | period + warehouse_id、warehouse_id + status、created_at |
| expenses | order_id + created_at |
| cash_txns | occurred_at、account_id + occurred_at、ref_type + ref_id |
| audit_logs | created_at、module + created_at |
| counters | 默认主键 |

> 关键字模糊搜索（正则）无法走索引。即使控制台漏建索引，列表类查询也会自动退化为内存排序，不会直接报“索引缺失”；但数据量大时仍建议补齐上面的组合索引。

## 三、多角色使用

| 角色 | 能做什么 | 看不到什么 |
|------|----------|------------|
| 老板 owner | 全部 | — |
| 运营 operator | 商品、供应商、采购、库存入出、订单、费用录入 | 用户管理 |
| 仓库 warehouse | 收货入库、盘点、发货、查库存 | **进价、平均成本、毛利、库存金额**（服务端裁剪） |
| 财务 finance | 费用、报表、供应商维护、查订单 | 用户管理 |
| 客服 service | 查订单、查库存 | **成本与毛利** |

新增成员流程：对方先打开一次小程序 → 在「我的」页复制 openid → 老板进入「我的 → 用户与权限」粘贴 openid、选角色。

## 四、核心口径（已在代码中固化）

- 收入唯一口径：`orders.paid_amount`（实收）。
- 商品成本：移动加权平均；订单保存时写入 `items[].cost_snapshot`，事后进货不影响历史毛利。
- 入库：`入库总成本 = 进价 × 数量 + 分摊运费 + 其他费用`，按明细金额比例分摊；`新均价 = (原数量×原均价 + 入库总成本) ÷ (原数量+入库数量)`。
- 毛利：`实收 - 商品成本 - 快递 - 包装 - 赠品 - 介绍费 - 平台佣金 - 支付手续费 - 其他`。
- 仓库未填进价入库时，按当前平均成本入账，避免把成本摊薄为 0。
- 发货扣库存并写 `销售出库` 流水；已发货订单退款自动回补 `退货入库`。
- 现金流：订单保存/退款时自动同步一笔 `销售回款` 收入与 `售后退款` 支出（按订单当前实收和累计退款整体重算，不会重复记账）；未指定默认账户时自动创建「默认账户」。手工登记的资金流水不受影响。
- 盘点：盘点单状态为「盘点中」时，服务端暂停采购入库、销售出库、退货入库、调拨和手动调整，避免盘点结果被并发改写；完成盘点会按实盘数生成盘盈/盘亏流水。
- 盘点支持按商品「默认供应商」抽盘：创建盘点单时可只带入某供应商的商品，盘点录入页也可按供应商筛选；商品编辑页可维护默认供应商。
- 已收款订单不能直接取消，必须走退款流程；未收款订单可取消并保留单据。
- 所有写操作写 `audit_logs`（操作人、前后值、摘要）。

## 五、已完成范围

- M1：商品、供应商、采购单（采购渠道/采购订单号/物流单号、创建/收货入库/运费分摊）、库存列表/详情/流水、手工入库、月度盘点、手动库存调整（带原因）、移动加权成本、扫码、多仓调拨。
- 订单：自仓/代发、发货填写快递单号（写入订单与销售出库流水）、售后退货退款、自动现金流、毛利核算。
- M2：手工开单（多商品、成本快照）、发货、完成、取消、退款、售后单、代发、费用归集、订单毛利、自动现金流。
- M3 基础：首页 KPI、利润/库存/渠道/费用报表、5 角色权限矩阵、服务端字段裁剪、用户与审计日志。
- 未做：平台 CSV 导入、平台对账、导出 CSV、消息通知。

## 六、人工验收清单（需在开发者工具/真机执行）

1. 初始化后首页出现 6 个指标与待办。
2. 新增商品 → 采购单含 2 个商品 + 运费 → 收货入库 → 库存出现数量与平均成本。
   手算校验：均价 = (原数量×原均价 + 进价×数量 + 分摊运费) ÷ 新数量。
3. 同一商品再入一笔不同进价，均价按移动加权变化；历史订单毛利不变。
4. 新建订单（含快递费、赠品、介绍费）→ 详情页毛利与手算一致。
5. 发货：库存减少、流水出现「销售出库」；库存不足时发货被拦截。
6. 已发货订单退款：库存回补、流水出现「退货入库」。
7. 把某成员设为仓库：重新进入后商品详情/采购单/报表看不到成本、均价、毛利字段（接口返回即无该字段）。
8. 盘点：实盘数大于/小于账面，生成盘盈/盘亏流水。
9. 盘点单处于「盘点中」时，采购入库、发货、退货入库、调拨、手动调整都会被拦截并提示先完成盘点。
10. 发货必须填写快递单号，订单详情可查看；采购单支持采购渠道、采购订单号、物流单号，入库后仍可补录。
11. 商品设置默认供应商后，创建盘点单可按该供应商抽盘，盘点页也能按供应商筛选。
12. 订单保存后现金流出现「销售回款」，退款后出现「售后退款」；重复保存不会重复记账。
13. 未收款订单可取消并保留单据；已收款订单取消会被拦截，需走退款。
14. 审计日志能看到新增商品、入库、发货、退款等写操作。

## 七、已知限制

- 云开发单文档 1MB、事务仅支持有限操作；当前单店数据量足够，后续可迁云托管 MySQL（前端接口不变）。
- 盘点单明细存在单个文档里，商品数接近数千时可能触及 1MB 上限；页面已按 50 条分页渲染并只提交改动项，超大目录建议分仓盘点。
- 弱网离线草稿、CSV 批量导入未实现。
- 云函数默认超时 3 秒不够初始化，务必按第 4 步调整。
