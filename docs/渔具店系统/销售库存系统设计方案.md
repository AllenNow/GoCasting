# 渔具销售与库存管理系统 · 设计方案

> 版本：v0.1（设计稿，待评审）
> 日期：2026-11-24
> 形态：微信小程序（内部管理工具）
> 范围：单店、单人为主、可扩展到 4 个使用角色
> 与 GoCasting：本期不打通，数据模型预留字段

---

## 一、目标与边界

### 1.1 要回答的四个问题

这套系统不是为了“记一笔账”，而是让每天 5 分钟内看清四件事：

| 问题 | 对应能力 |
|------|----------|
| 这一单到底赚了多少钱？ | 订单级真实毛利：售价 - 商品成本 - 快递 - 包装 - 赠品 - 介绍费 - 平台佣金 - 支付手续费 |
| 哪个 SKU 在赚钱，哪个在压钱？ | 单品毛利、动销率、库龄、周转天数 |
| 哪个渠道值得继续投？ | 渠道销售额、毛利、费用、ROI |
| 未来 3 个月现金够不够？ | 现金余额、应收应付、固定支出、库存占用 |

### 1.2 做什么 / 不做什么

**做：**

- 商品与 SKU、供应商与进货渠道
- 采购入库（含进仓运费分摊）、库存流水、移动加权成本
- 订单录入与平台 CSV 导入、发货、退款
- 费用归集：快递费、介绍费、赠品、包装、推广
- 毛利与库存报表、角色权限、审计日志
- 手机扫码出入库

**不做（本期）：**

- 完整财务总账、发票管理、税务申报
- 多公司/多门店、复杂审批流
- 自动抓取平台订单（接口不稳定且合规风险高）
- 面向消费者的商城功能（避免小程序类目与支付资质问题）
- 与 GoCasting 的订单/装备联动

## 二、多视角分析

同一套数据，四个角色看到的东西不同。设计时先把冲突摆出来，再决定取舍。

| 视角 | 最关心 | 会推动的设计 | 潜在冲突 | 本方案的取舍 |
|------|--------|--------------|----------|--------------|
| 老板 | 真实现金与净利 | 一屏看板、所有成本可见 | 想看全部，但不想每天录很多 | 首页只放 6 个指标；单据尽量扫码/导入 |
| 运营 | 动销、渠道、活动效果 | SKU 标签、渠道对比、赠品模板 | 促销赠品多，容易漏记成本 | 赠品做成“出库类型”，自动计入订单成本 |
| 财务 | 对账、费用归集口径 | 平台账单导入、费用分类、导出 | 与运营的“销售额”口径不一致 | 全系统统一“实收金额”为唯一收入口径 |
| 仓库 | 库存准、发货快 | 扫码、待发货列表、缺货预警 | 不想看到进价与毛利 | 字段级权限：仓库看不到成本与利润 |
| 开发 | 先跑通、少维护 | 云开发、少依赖、服务端聚合 | 一次做全 vs 先验证 | M1 只做“进-存-销-利”闭环，其余后置 |

**三个关键口径，先定死：**

1. **收入 = 实收金额**（买家实付，扣除优惠后），不是商品标价，也不是平台结算额。
2. **商品成本 = 移动加权平均成本**，入库时把进仓运费摊进成本；不做到批次成本。
3. **费用按“能归因就归因”原则**：能落到订单的落订单（快递、介绍费、赠品），落不到的按月分摊（推广、设备）。

## 三、角色与权限设计

### 3.1 角色定义

| 角色 | 典型使用者 | 核心职责 |
|------|-----------|----------|
| 老板 Owner | 本人 | 全部数据、成本、利润、用户管理 |
| 运营 Operator | 本人/配偶 | 商品、采购、订单、促销、赠品 |
| 仓库 Warehouse | 配偶/兼职 | 入库、出库、盘点、发货 |
| 财务 Finance | 本人/配偶 | 费用、对账、报表、导出 |
| 客服 Service（可选） | 兼职 | 订单查看、备注、售后 |

### 3.2 功能权限矩阵

| 模块 | 老板 | 运营 | 仓库 | 财务 | 客服 |
|------|------|------|------|------|------|
| 首页看板 | 全部 | 销售/库存 | 待发货/缺货 | 利润/现金 | 订单概况 |
| 商品 | 增删改查 | 增改查 | 只读（无成本） | 只读（含成本） | 只读（无成本） |
| 供应商/渠道 | 增删改查 | 增改查 | 只读 | 只读 | 无 |
| 采购单 | 全部 | 创建/查看 | 收货/入库 | 查看/付款 | 无 |
| 库存 | 全部 | 查看 | 入出库/盘点/调拨 | 查看 | 只读可用量 |
| 订单 | 全部 | 全部 | 查看/发货 | 查看 | 查看/备注/售后 |
| 费用 | 全部 | 新增 | 无 | 全部 | 无 |
| 报表 | 全部+导出 | 销售/渠道 | 库存 | 全部+导出 | 无 |
| 用户与设置 | 全部 | 无 | 无 | 无 | 无 |

### 3.3 字段级权限（比功能权限更重要）

| 字段 | 老板 | 运营 | 仓库 | 财务 | 客服 |
|------|------|------|------|------|------|
| 进价、平均成本 | 可见 | 可见 | **隐藏** | 可见 | **隐藏** |
| 单笔毛利、毛利率 | 可见 | 可见 | **隐藏** | 可见 | **隐藏** |
| 供应商结算方式 | 可见 | 可见 | 隐藏 | 可见 | 隐藏 |
| 买家手机号/地址 | 可见 | 可见 | 发货时可见 | 隐藏 | 可见 |

> 实现方式：权限判断放在云函数，返回数据前裁剪字段；前端隐藏只是体验，不作为安全边界。

### 3.4 审计

所有写操作记录 `audit_log`：谁、什么时候、改了哪张表哪条记录、改前改后。成本与价格变更必须留痕，防止“账对不上但不知道谁改的”。

```
供应商 ──< 采购单 ──< 采购明细 >── 商品SKU
                                    │
仓库 ──< 库存 >─────────────────────┘
         │
         └──< 库存流水 >── 采购单/订单/盘点单

订单 ──< 订单明细 >── 商品SKU
  │
  ├──< 费用（快递/介绍费/赠品/包装）
  └──< 退款

用户 ── 角色 ── 权限
```

| 字段 | 说明 |

| 字段 | 说明 |
|------|------|

| 字段 | 说明 |

- 权限用“模块 + 动作”编码，如 `order:read`、`cost:read`
- 审计日志记录写操作

## 五、核心算法与口径

### 5.1 入库成本

```
入库总成本 = 进价 × 数量 + 分摊运费 + 分摊其他费用
单位入库成本 = 入库总成本 ÷ 数量
```

### 5.2 移动加权平均成本

```
新平均成本 = (原库存数量 × 原平均成本 + 本次入库总成本)
             ÷ (原库存数量 + 本次入库数量)
```

### 5.3 单笔订单毛利

```
毛利 = 实收金额
       - 商品成本（cost_snapshot × 数量）
       - 快递费
       - 包装费
       - 赠品成本
       - 介绍费
       - 平台佣金
       - 支付手续费
       - 分摊推广费
       - 售后损耗
```

> 成本必须用**下单时的快照**，不能事后用最新平均成本回算，否则历史毛利会随进货价波动。

### 5.4 库存与动销指标

| 指标 | 公式 |
|------|------|
| 库存周转天数 | 期末库存成本 ÷ 期间销售成本 × 期间天数 |
| 动销率 | 有销量的 SKU 数 ÷ 在售 SKU 数 |
| 库龄 | 按入库时间分 0-30 / 31-60 / 61-90 / 90+ 天 |
| 滞销 | 90 天无销量且库存 > 安全库存 |
| 缺货预警 | 可用库存 + 在途 < 安全库存 |

### 5.5 渠道 ROI

```
渠道 ROI = (渠道毛利 - 渠道费用) ÷ 渠道费用
```

渠道费用包括：平台佣金、推广费、介绍费、活动赠品。

### 5.6 现金流（简版）

```
期末现金 = 期初现金 + 本期实收 - 采购付款 - 费用支出 - 债务利息
```

不做到权责发生制，先按“钱有没有到账/付出”记账，够小店用。

## 六、关键业务流程

### 6.1 采购入库

```
新建采购单 → 选供应商 → 加 SKU/数量/进价 → 填运费
→ 到货验收 → 入库（生成流水、更新平均成本）
→ 付款（现结或挂应付）
```

- 部分到货：支持分批入库，未到部分留在“在途”
- 运费分摊：按金额或按数量，默认按金额
- 赠品进货：进价 0 或按实际，单独标记

### 6.2 销售出库

```
订单录入 / CSV 导入 → 匹配 SKU → 锁定库存
→ 填快递费/赠品/介绍费 → 发货（扣库存、写成本快照）
→ 确认收货 → 计入毛利
```

- 手工单与平台导入共用一套订单表，用 `platform + platform_order_no` 去重
- 快递费支持“预估 + 实际”两次录入，月末按实际调整
- 介绍费支持固定金额或按比例，记录收款人，可生成应付

### 6.3 退款与售后

```
发起退款 → 状态变更 → 库存回补（未发货）或计入损耗（已发货）
→ 收入冲减、成本回冲、费用冲减 → 更新毛利
```

### 6.4 盘点

```
选择仓库 → 扫码盘点 → 生成差异 → 确认调整
→ 盘盈按当前平均成本入账，盘亏计入损益
```

### 6.5 代发

- 建“虚拟仓”，代发商品不占自仓库存
- 订单走代发时，记录供应商成本与代发运费，毛利口径不变
- 代发供应商只读对账视图，不开放其他数据

### 6.6 赠品与礼品

- 赠品如果是自有商品：走“赠品出库”，成本计入订单
- 赠品如果是外购礼品：记 `expense.type = 赠品`，关联订单
- 两种方式必须二选一，避免重复计成本

## 七、报表与看板

### 7.1 老板首页（6 个指标）

| 指标 | 说明 |
|------|------|
| 今日/本月销售额 | 实收口径 |
| 今日/本月毛利、毛利率 | 扣除全部可归因费用 |
| 现金余额 | 手动维护 + 收支流水 |
| 库存总值 | 按平均成本 |
| 滞销 SKU 数 | 90 天无销量 |
| 待办 | 待发货、缺货、待对账、待付款 |

### 7.2 报表清单

| 报表 | 维度 | 用途 |
|------|------|------|
| 利润明细 | 订单/商品/渠道/时间 | 看真实利润 |
| 商品动销 | SKU | 决定补货与清仓 |
| 库存库龄 | SKU/仓库 | 发现压货 |
| 渠道对比 | 平台 | 决定投放 |
| 费用结构 | 类型/月 | 控制成本 |
| 平台对账 | 平台/账期 | 找差异 |
| 现金流 | 月 | 看能不能撑住 |

### 7.3 图表

- 小程序端不做复杂图表，只做趋势线 + 排行 + 进度条
- 复杂分析用“导出 CSV → 电脑看”，避免小程序性能与包体积问题

## 八、小程序信息架构

### 8.1 底部导航

| Tab | 内容 |
|-----|------|
| 首页 | KPI 卡片、待办、快捷入口（扫码入库/开单） |
| 订单 | 列表、筛选、详情、新建、导入、发货、退款 |
| 库存 | SKU 列表、详情、入库、出库、盘点、调拨 |
| 报表 | 利润、动销、库龄、渠道、费用、现金流 |
| 我的 | 角色与权限、供应商、仓库、设置、导出、审计 |

### 8.2 关键交互

- **扫码**：扫条码直达 SKU，入库/出库各一步
- **拍照**：进货单、快递单拍照存证，挂到单据
- **离线草稿**：弱网时先存本地，恢复后同步
- **批量导入**：平台订单 CSV，先预览匹配结果再确认
- **字段隐藏**：无权限字段直接不返回，不显示“无权查看”占位

### 8.3 小程序约束

- 类目选“工具-效率”，不做商品购买与在线支付，避免电商资质
- 包体积控制：图表用轻量方案，图片走云存储
- 登录：微信登录 + 手机号绑定，后台分配角色
- 数据导出：生成 CSV 存云存储，小程序内提供下载链接

## 九、技术方案（建议）

| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | 微信小程序原生 + TypeScript | 依赖少、包小、扫码能力强 |
| 后端 | 微信云开发（云函数 + 云数据库） | 免运维、成本低，适合单人维护 |
| 数据库 | 云数据库（文档型） | 起步快；若后续事务复杂，迁云托管 MySQL |
| 文件 | 云存储 | 进货单、快递单、商品图 |
| 图表 | ec-canvas | 轻量，够用 |
| 定时任务 | 云函数定时触发器 | 每日备份、滞销计算 |
| 备份 | 每日导出 JSON/CSV 到云存储，保留 30 天 | 防误删 |
| 成本 | 基础用量约 ¥0-50/月 | 远低于自建服务器 |

**为什么不用自建后端：** 当前是单人 + 少量订单，云开发能覆盖 90% 需求；等订单量或事务复杂度上来，再把数据层换成 MySQL，前端不动。

**事务注意：** 入库/出库涉及“流水 + 库存 + 成本”三处写入，云函数里用数据库事务或幂等重试，避免半成功。

## 十、权限实现要点

1. 云函数统一入口鉴权：解析 openid → 查用户角色 → 校验 `module:action`
2. 字段裁剪在服务端完成，前端拿不到成本字段
3. 高危操作二次确认：删除商品、修改历史成本、红冲订单
4. 审计日志不可删除，只能追加
5. 角色变更立即生效，旧 token 不缓存权限

## 十一、MVP 范围与验收

### M0 设计评审（本文档）

- 确认成本口径、角色数量、后端选型
- 确认费用类型清单

### M1 进销存闭环

- 商品、供应商、采购入库、库存流水、平均成本
- 验收：入库 3 笔不同运费，平均成本计算正确；库存流水可追溯

### M2 订单与毛利

- 手工开单、CSV 导入、发货、退款、费用归集
- 验收：一笔订单包含快递、赠品、介绍费，毛利与手算一致

### M3 报表与权限

- 首页 KPI、利润表、动销、库龄、渠道
- 4 个角色权限与字段隐藏
- 验收：仓库账号看不到任何成本与毛利字段

## 十二、风险与取舍

| 风险 | 影响 | 应对 |
|------|------|------|
| 手工录入负担重，用不起来 | 高 | 扫码 + CSV 导入 + 默认值；每日录入控制在 5 分钟 |
| 成本口径反复变 | 高 | M0 定死移动加权；历史订单一律用快照 |
| 赠品与介绍费漏记 | 中 | 订单提交前校验“是否含赠品/介绍费”开关 |
| 小程序类目审核 | 中 | 定位内部工具，不做消费者商城与支付 |
| 云开发事务能力有限 | 中 | 关键写入用事务/幂等；数据量上来迁 MySQL |
| 权限泄露成本 | 中 | 服务端字段裁剪 + 审计 |
| 平台账单对不上 | 中 | 单独对账表，差异必须填原因 |
